---
title: Coming from Playwright
description: A Playwright (JavaScript) to KMPwright mapping for lifecycle, navigation, locators, assertions, network, storage, emulation, input, dialogs, frames, downloads, screenshots and tracing, plus the differences that matter.
---

KMPwright uses Playwright's JavaScript names and shapes wherever Kotlin allows. If you know Playwright, most code translates line by line:

```kotlin
// await page.goto('https://example.com');
page.goto("https://example.com")
// await page.getByRole('button', { name: 'Save' }).click();
page.getByRole("button", name = "Save").click()
// await expect(page.getByText('Saved')).toBeVisible();
expect(page.getByText("Saved")).toBeVisible()
// await page.route('**/api/**', r => r.fulfill({ json: { ok: true } }));
page.route("**/api/**") { route -> route.fulfill(json = """{"ok":true}""") }
```

The naming rules, in order:

1. **Playwright JS** names and shapes.
2. **Playwright Java** names where the JS name is a Kotlin keyword: `route.resume()` for `route.continue()`.
3. **agent-browser** names for agent features: `snapshot()`, `@e3` refs, `setAllowedDomains`, `runCommand`.
4. **Kotlin idioms** only where needed: `suspend` instead of Promises, named parameters instead of option objects, flows instead of `page.on(...)`, `timeoutMs: Long?`, `use {}` for cleanup.

Playwright option objects become Kotlin named parameters with the same names: `page.screenshot({ fullPage: true })` is `page.screenshot(fullPage = true)`, and `locator.click({ button: 'right', force: true })` is `locator.click(button = MouseButton.Right, force = true)`. Every `timeout` becomes `timeoutMs: Long?` (milliseconds; `null` uses the configured default), and every `delay` becomes `delayMs`.

The tables below list every Playwright API with a KMPwright counterpart. "—" means there is none. Snippets assume `page: Page`.

## Assertions

`expect(locator)` returns `LocatorAssertions`; `expect(page)` returns `PageAssertions`. Each assertion re-reads until it holds or `timeoutMs` (default `TimeoutConfig.waitForSelector`) passes, then throws `KmpwrightTimeoutException`. Use `.not` to negate.

| Playwright (JS) | KMPwright | Notes |
| --- | --- | --- |
| `toBeVisible()` / `toBeHidden()` | same | |
| `toBeAttached()` | `toBeAttached()` | No `{ attached: false }`; use `.not.toBeAttached()`. |
| `toBeEnabled()` / `toBeDisabled()` | same | |
| `toBeChecked()` | `toBeChecked()` | No `{ checked: false }`; use `.not`. |
| `toBeFocused()` / `toBeEditable()` / `toBeEmpty()` | same | |
| `toHaveText(text)` | `toHaveText(String)` / `toHaveText(Regex)` | Whitespace-normalised `innerText`; full match for strings. No array form. |
| `toContainText(text)` | `toContainText(String)` / `toContainText(Regex)` | |
| `toHaveValue(value)` | `toHaveValue(String)` / `toHaveValue(Regex)` | |
| `toHaveAttribute(name, value?)` | `toHaveAttribute(name)`, `(name, String)`, `(name, Regex)` | |
| `toHaveClass(cls)` | `toHaveClass(String)` / `toHaveClass(Regex)` | String compares the whole normalised `class` attribute. |
| `toHaveCount(n)` | `toHaveCount(n)` | |
| `expect(page).toHaveURL(url)` | `expect(page).toHaveURL(String)` / `(Regex)` / `{ url -> … }` | String is a URL glob; without glob characters it must equal the URL. |
| `expect(page).toHaveTitle(title)` | `expect(page).toHaveTitle(String)` / `(Regex)` | |
| `toHaveCSS`, `toHaveId`, `toHaveJSProperty`, `toBeInViewport`, `toHaveAccessibleName`, `toHaveRole`, `toHaveValues`, `toHaveScreenshot`, `toMatchAriaSnapshot`, `expect.poll`, `expect.soft` | — | Use `locator.evaluate(...)` with your own check, or `page.visualDiff(...)` for images. |

## Differences to keep in mind

**`suspend` instead of `await`.** Every operation that touches the page is a `suspend` function. There are no Promises to forget to await, but you need a coroutine scope.

**`use {}` instead of `try`/`finally`.** `Browser`, `BrowserContext`, `Page` and `LaunchedBrowser` have `use { }`, which closes them when the block ends, even when it throws or is cancelled, like Kotlin's `Closeable.use` and Ktor's `HttpClient.use`:

```kotlin
browser.newPage().use { page ->
    page.goto("https://example.com")
    page.screenshot(fullPage = true)
}
```

**State as flows.** `page.url` and `page.title` are `StateFlow`s you can read (`.value`) or collect. `page.events` exposes hot `SharedFlow`s (`console`, `navigation`, `loadState`, `dialog`, `request`, `response`, `download`, `fileChooser`) instead of `page.on(...)`. Subscribe before you trigger the action, or use the action-scoped helpers (`waitForNavigation { }`, `waitForResponse(url) { }`, …), which subscribe for you.

**Options are named parameters.** `page.goto(url, waitUntil = LoadState.DOMContentLoaded)`. Kotlin's named and default arguments replace option objects; the names match Playwright's, except `timeout` → `timeoutMs`, `delay` → `delayMs` and screenshot `type` → `format`. `timeoutMs` comes after the other options (only a trailing lambda follows it).

**Timeouts are `timeoutMs: Long?`.** `null` (the default) means "use the configured default" from `KmpwrightConfig.timeouts`: `navigation` for navigations, `action` for locator actions, `waitForSelector` for assertions, `default` for everything else. All four default to 30 000 ms. Timeouts throw `KmpwrightTimeoutException`; other failures throw `KmpwrightException`.

**Strict selectors.** By default a locator action that matches more than one element fails, like Playwright. `KmpwrightConfig(strictSelectors = false)` relaxes this.

**No element handles.** Everything goes through lazy locators. `page.evaluate` takes an expression string; `locator.evaluate` takes a function string such as `"el => el.value"`.

**String URL patterns.** `route`, `unroute`, `waitForURL`, `waitForRequest`, `waitForResponse`, `waitForNavigation(url = …)`, `waitForDownload` and `expect(page).toHaveURL` use Playwright's URL glob over the full URL; a string without glob characters is an exact URL. A `regex:` prefix makes the string a regular expression where there is no `Regex` overload (such as `waitForDownload`). Prefer the `Regex` overloads where they exist.

**Capabilities instead of "it just works".** Check what the backend can do before you depend on it:

```kotlin
page.requireCapabilities(PageCapability.Downloads)                    // fails fast if not Supported
page.requireCapabilities(PageCapability.RouteInterception.require(SupportLevel.Partial))
val level = page.capabilities().supportLevel(PageCapability.VideoRecording)
val why = page.capabilities().notes                                   // human-readable gaps
```

### Not supported

- Firefox and WebKit desktop browsers. The JVM backend is Chromium over CDP; mobile backends are the system WebViews.
- A test runner. There is no `@playwright/test` equivalent (fixtures, projects, retries, reporters); use your own test framework and call `expect`.
- Codegen, the inspector, `page.pause()`, Playwright trace viewer files.
- Element handles, `evaluateHandle`, `exposeFunction`, `exposeBinding`.
- `route.fetch`, `routeFromHAR`, WebSocket routing.
- Context options without a runtime setter: `locale`, `timezoneId`, `permissions`, `reducedMotion`.
- Visual assertions (`toHaveScreenshot`). `page.visualDiff(expected, actual)` compares two `ScreenshotResult`s.

### Mobile WebView limitations

On Android `WebView` and iOS `WKWebView`, KMPwright runs inside an app's view rather than a browser it controls, so:

- Input is synthesized as DOM events, not trusted OS input. Mouse and (on iOS) keyboard input are Partial.
- Routing covers what the platform exposes: Android `shouldInterceptRequest`; iOS fetch/XHR through a bridge plus optional custom-scheme interception. Neither sees every request a desktop browser would.
- No downloads, file chooser, `setInputFiles`, tracing, profiling, video or screencast.
- Network emulation is offline-only.
- Android has no isolated browser contexts; cookies are shared by every `WebView` in the process.
- Frames are limited to same-origin documents.

See [Capabilities](/docs/platforms/capabilities) for the full matrix and each backend's notes.
