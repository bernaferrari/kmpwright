## Applied changes

- Build and CI need no upstream checkout; only provenance metadata is published.
- CDP omits null session IDs, allocates IDs atomically, preserves message order, isolates malformed messages, and serializes WebSocket writes.
- HTML content loading preserves spaces and awaits the new document.
- Select matches values or normalized labels and rejects missing/disabled options before changing selection.
- Snapshots preserve DOM identity across captures, resolve refs to live nodes, and reject invalid/missing scopes.
- Snapshot diffs read the old baseline before replacing it.
- ARIA label lookup joins IDREFs without unsafe CSS interpolation.
- Browser Use uses Cloud v4; Kernel uses structured profiles, modern response names, and authenticated cleanup.
- JVM supports CDP file-input upload and awaits Promise-based selector waits. Selector, text, and function waits use bounded polling when a WebView bridge cannot await a Promise; function timeouts fail explicitly.
- Same-origin frame locators query the frame document, including nested frames; missing selector chains stay empty.
- HAR embeds available text/base64 response bodies and exports the standard log envelope.
- ScreenshotTracker implements bounded, scoped conditional captures with pixel thresholds. iOS now decodes image bytes into straight RGBA using CoreGraphics instead of its former stub.
- Domain-filter wildcard matching agrees with the Kotlin matcher; new WebRTC/workers are blocked under an active allowlist.

## Parity boundaries and remaining work

Kmpwright is a typed browser library, while agent-browser also ships a daemon, CLI, MCP server, plugins, providers, streaming UI and experimental engines. Browser recording and HTTP reading belong to the requested Kotlin API scope; recording now has a CDP/FFmpeg implementation with trusted pointer observation and fixed-rate cursor composition. CLI, daemon, MCP server, plugin and chat-gateway equivalents are excluded by the owner. Mobile WebViews cannot promise the same isolation, event trust, network interception, or process-level containment as a launched Chromium instance.

Browser APIs cover native Chromium AX hierarchy and input, cross-process frames, WebMCP, axe, React/Vitals, setup inheritance, recording, HAR, login, autosave, owned launch and profile snapshots. Live Darwin document execution and Linux NSS/WebGPU integration remain verification limits. Native WebView capability constraints and experimental engine exclusions remain explicit. Page-created contexts, preexisting service workers, and externally launched browsers prevent treating domain filtering as a security sandbox. The implementation checklist is [parity-work.md](parity-work.md).

Prefer locator/text/predicate waits for application readiness. `NetworkIdle` can be prevented by persistent activity and is not proof that an application has finished updating.
